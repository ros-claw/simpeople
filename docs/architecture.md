# 运行与证据结构

控制端 CLI 和 stdio MCP 调用同一个本地 HTTP 桥。桥的网络线程只接受和排队 JSON，Kit 主线程完成校验、控制权交接和动作调用。任务监督器跟踪 episode、控制 epoch、步骤游标、资源租约与实际观测；原生 Behavior 独占人物的动画和根运动。

普通单人物及 Kit 扩展使用 NativeBackend。独立工业场景使用 ReservationNativeBackend，把路线请求编排成原生 move_to 子任务；路径在烘焙后的 NavMesh 网格上规划，当前人物占用和前方预约共同决定可走空间。没有对根或骨骼施加避碰位置修正。

路线以 route- 开头的 ID 标识监督器任务，对外位于 backend_task_id。native_task_id 只报告真实原生 ID；每段原生调用与原始结束回调另存事件。路线最终成功仍需实际到达、低速度、稳定时间等检查。预约等待为 blocked，有原生日志和有限动作超时。

坐下需要座位租约、Hips 标记、朝向、脚高和稳定时间。通行控制先走到座位接近点，并预约最后一段坐姿交互空间。离座先触发原生起身，之后走到空闲的让出点，实际停稳才释放座位。异常恢复不通过传送完成。

外部事件由调用者提供明确的人物集合与来源。固定策略包含优先级、仿真时间去抖和恢复规则；普通事件延后到交互安全边界，手动指令和取消能使旧事件失效。角色响应也有带 seed 的定时本地事件，运行时不逐帧调用语言模型。

Kit 扩展以独立会话图层与唯一顶层命名空间附着当前场景。编辑目标在每次写入后恢复；卸载移除自有会话层和原生输出层中的自有命名空间。真实生命周期测试验证原场景根图层不变、已有对象仍存在。该扩展不会替用户重建 NavMesh、相机或场景。

每次独立运行冻结源码、配置和能力表，并保存逐文件 SHA256。实际轨迹来自 Behavior 运行时与关节世界变换，速度按实际仿真时间差分；SDK 原始速度仍单列。首次 30 s wall 为性能预热，实际采集吞吐、RTF、进程资源和共享 GPU 总负载分别报告。

原始帧文件按仿真帧编码，配有逐帧 sim/wall 时间戳。墙钟导出以不重编码的可变帧率重封装保留每帧实际显示时长；ffprobe 独立核验全部时间戳。两份录像均保留，编码帧率不作为实时性能。

几何质量监测的根胶囊代理与位移跳变定义保存在 quality_audit.json。它用于发现需要检查的时间段，不能替代近景录像、精确 mesh 碰撞或机器人传感器验收。task 状态成功不覆盖几何失败，持续时间通过也不覆盖穿透问题。
