---
name: simpeople
description: Arrange and control animated people or crowds in an Isaac Sim scene through SimPeople tools; use for creating people, assigning activities, live goal changes, crowd summaries, cancellation, and simulation evidence.
---

Use the installed SimPeople MCP tools. Runtime tasks continue independently of the MCP connection. Do not write USD transforms or bones from another script.

1. Call `people_session` with `action=info`, then `action=preflight`. Check session/episode identity, public coordinate frame, NavMesh, semantic places and asset availability. Bind writes to the observed `session_id` and `episode_id`; use `actor_instance_id` when binding a plan to a particular actor instance. Refresh scope after reset or reconnect. A missing NavMesh, seat calibration or asset is a concrete blocker to report. Never silently substitute another scene or idle animation.
2. Inspect assets and action capabilities before planning. `discovered` is not verified. Functional `sit` and geometric quality certification are separate. Arbitrary rigs and chairs are not automatically compatible. Read `docs/acceptance_criteria.md` from the runtime checkout when assessing capacity; a mode name does not establish real-time throughput.

   Capability names and activity verbs differ: `walk` and `run` are gaits. Walking uses `{"action":"move_to","target":[x,y,z],"gait":"walk"}`; native Jog uses the same action with `"gait":"run"`. Never submit `action: walk/run`. Read `activity_contract` in `people_list_actions` for the actual step verbs and required fields. Supply a duration for wait/sit/queue/follow/custom_action/head_look/reach_hand, and left/right hand for reach. Templates still require a real scene target and an actor-specific verified capability; they do not imply a new action is supported.

   For seats, queues, workstations and activity bays, query `people_list_interactions` and use `people_validate_interaction` with the selected actor, action and returned geometry revision. These are advisory reads: a clear preflight acquires no slot or corridor. Inspect current occupancy and actor-specific quality separately. Unknown props have no inferred interaction actions. Native `head_look` and single-hand `reach_hand` require exact-asset verified entries in `people_list_actions`; honor their domain and maximum hold duration, settle the actor first, and supply `hand: left/right` for reach. Legacy `look_at` turns the body. Gesture completion includes native return; it does not prove grasping or force. If an older runtime lacks these tools, retain legacy inspection and report revision binding unavailable.
3. Acquire control with `people_session(action=acquire, request_id=...)` before writes. If another client owns it, keep observing. Only take over when the user requested it; read current epoch and use explicit `action=takeover, expected_epoch=...`. Local ownership coordinates clients; it is not authentication.
4. For one actor, validate the complete activity before submitting. For crowds, use `people_crowd(operation=run_activity, selector=..., steps=...)`, or individual `items`. Select by `actor_ids`, `role`, `group`, or `region_m=[xmin,ymin,xmax,ymax]`. Batch size is at most 100; inspect each item because partial acceptance is possible. On runtimes reporting `session_info.batch_contract.version=2`, batch activity items accept `actor_id`, `steps`, optional `actor_instance_id`, `if_busy` and `on_blocked`; keep those policies inside each item. Bind the observed instance ID when planning for an existing person. A stale instance rejects only that item and preserves the recreated actor. Cancellation items can bind `actor_instance_id` with `actor_id` or `task_id`; both IDs must refer to the same actor. Unknown item fields are rejected before the batch writes anything, with the field names and allowed fields returned. If that contract is absent, use legacy `actor_id`/`steps` batch items; use individual instance-bound `run_activity` calls when an older runtime cannot bind batch items. Spawn batches require explicit items with actor IDs, assets and anchors.

   For a one-time crowd instruction, resolve role/group/region selectors through `people_crowd(operation=state)` and follow `next_offset` through every selected page. Save the actual `actor_id` and `actor_instance_id` values before validating, deduplicate actor IDs, and refresh selection if the same ID appears with conflicting instances. Submit explicit instance-bound items or the fixed `selector.actor_ids`. Reuse this fixed set for monitoring and local repairs; later membership changes must not add people to this command. Pagination is not an atomic scene snapshot: restart selection if the session or episode changes. A request to continuously manage arrivals needs its own event workflow rather than silently turning a one-time selection into a moving target. After partial acceptance, repair only affected members; retain successful task IDs and preserved actors. For uncertain delivery, retry the original request ID with identical parameters before creating a repair request.

   For repeated shared interactions, plan where each actor goes after egress. A completed queue task can leave a body occupying an exit and block later users. Use distinct reachable follow-up destinations when the requested activity implies moving on; preserve explicit instructions to wait.

   Bind `sit`/`queue` steps with `interaction_revision` from the target query. For version-bound workstation waits or bay clips, also supply their explicit `resource_id`; a custom clip must match the bay's registered clip. Runtime checks the geometry again while executing. On `TARGET_STALE`, query fresh geometry and validate the intended action before a new attempt; preserve the original result. Registry revisions exclude live occupancy, so another person joining a queue does not invalidate geometry by itself.
5. Every write requires a unique `request_id`. Retry uncertain delivery with the same ID and identical parameters. Accepted means submitted; poll each returned task ID until `succeeded`, `failed` or `cancelled`. Do not report accepted plans as completed animation.
6. For normal monitoring call `people_crowd(operation=state)` for summary and paginated actors. Request `details=true` only for specific actors. Read `people_crowd(operation=events, after=cursor)` incrementally; if `history_gap=true`, refresh state because bounded event history has rolled over.
7. To change goals, submit validated new activities for only the selected actors. Use `if_busy=reject` to preserve existing work; the default supersede invalidates the old plan and control epoch immediately, without certifying a physical stop. Other actors continue. After reconnecting, query current runtime state before retrying old intentions under a new ID.
8. Cancel with `people_cancel` or a crowd cancel batch; poll until `cancelled` with `physical_stop_verified=true`. Cancellation acknowledgement alone does not prove the actor stopped. Seat and physical queue leases remain reserved until actual egress and settlement. Inspect `queue_cleanup` or seat cleanup if a new activity waits; a cleanup error can intentionally retain physical occupancy. Pause freezes simulation-clock waits. Reset removes managed actors and changes episode identity; it is not an ordinary cancel.
   When available, read `seat_cleanup` in `people_crowd(operation=state)`: `pending`, `phase`, `deadline_sim_time` and `remaining_sim_s` describe physical cleanup separately from the activity outcome. An activity can remain `failed` while its seat is still reserved and cleanup continues. Polling does not restart the original 15-second cleanup budget, and releasing the seat later does not turn the failed activity into a success. `exit_route_pending` means no movement command has been submitted; inspect actual observations and SDK task IDs before reporting that a person is walking. Missing observations or blocker IDs remain unknown; do not infer them from proximity.

9. When blocked, inspect `blocked_details`: reason, blockers, resource, ticket rank, retry time and remaining deadline. `ADMISSION_FULL` is an explicit capacity result; do not bypass it by continuously submitting new request IDs. On a supporting runtime, `on_blocked=replan_or_report` opts into at most two explicit same-goal recovery attempts across the activity, preserving the original deadline. Queue target resubmissions share that budget; ordinary avoidance and capacity polling are separate. `report` keeps supervision without higher-level goal replacement. Report unsupported policy or exhausted budgets from actual replies.

   If the runtime emits `traffic_path_search_wait`, match its task/route, actor instance and sample time to the current activity. `planner_phase` distinguishes unavailable start candidates, unavailable goal candidates, no grid path, and a blocked goal footprint. In `start_checks` / `goal_checks`, `false` is a failed check while `null` means that short-circuit rules did not execute it. A node outside `in_blocked_set` has not thereby passed swept clearance or its NavMesh connector. These are sampled planning observations: `grid_path_unavailable` does not establish `TARGET_UNREACHABLE`, and unknown `blocker_ids` do not identify a person or reservation as the cause. Preserve unknown causes, the original goal and deadline. Later native submission still needs actual movement and the activity's terminal outcome; older runtimes without these events retain the existing inspection path.
10. Retain real tool replies, task outcomes, trajectories and video for an audit. Include rejected, cancelled and unfinished requests alongside successes. Video encoding rate is not measured runtime FPS. Report actual RTF and wall-time update rate separately. Traffic waiting, animation sliding and long render frames are different observations.

Use public Z-up metre coordinates reported by preflight. A move step may include `via` waypoints. `people_signal_event` consumes explicit supplied events; it does not imply robot sensors exist. Crowd follow remains blocked where not accepted. No arbitrary Python evaluation is exposed by this plugin.

For optional generated assets, `people_motion` supports only `prepare`, `status` and `cancel`. It reports unsupported unless a local worker endpoint is configured. Supply a validated MotionSpec with actual context provenance; do not invent executed pose history. Poll with the returned `worker_instance_id`. This tool produces assets and does not publish or play them on an actor. A succeeded generation, worker cancellation or corrected endpoint is not proof of native retarget quality, a physical stop or continuous streaming. Use only separately qualified preloaded IDs through the existing activity interface.
